Notes from building Felix

How Felix works, why it is built the way it is, and what testing it against crashes and network splits has turned up.

    Before you loosen the timeout, run the old commit

    Intermittent failures in Felix's cluster tests kept turning out to be real bugs in the broker, so before loosening a timeout I now run the test against a commit from before the suspect change; three cases show what that finds.

  2. 17 October 202611 min read

    Acknowledged, then forgotten: a crash under periodic fsync

    Under Felix's default periodic fsync, a crashed broker could come back missing records it had acknowledged while the cluster still counted it as caught up; this is how review and the TLA+ model found it on the follower and leader sides, and what the fix costs.

  3. 17 October 20267 min read

    How we catch a 1% regression

    Felix's rule is that a release must not be measurably slower than the one before it; this is how same-runner A/B runs, a Welch's t-test and throwaway bisect PRs in GitHub Actions find a 1-2% loss, and why a single benchmark run can't.

  4. 16 October 202610 min read

    Our model said everything passed. It was checking nothing.

    Felix checks 107 TLA+ configurations in CI; this is about three times a passing check meant nothing, and the twin configurations, reachability checks and spec pairing we use to catch it.

  5. 16 October 202610 min read

    One slow subscriber shouldn't slow anyone else

    How Felix keeps one slow subscriber from holding up publishers or other readers, and how a 2% single-publisher loss came from where the feeder gave back a subscriber's byte budget.

  6. 15 October 20268 min read

    The data came back

    Deleting a Felix stream or cache and creating one with the same name could bring back the old one's data; this is how incarnations fixed it, and how we kept control-plane members on different releases from storing different answers during the rollout.

  7. 28 September 202612 min read

    Point your Kafka client at Felix

    Felix brokers speak enough of the Kafka wire protocol for Kafka producers and partition-assigning consumers to use durable Felix streams; this is how a Kafka request becomes a Felix operation, how idempotent sequences survive a failover, and exactly where compatibility stops.

  8. 27 September 20268 min read

    Ten parcels, one envelope: Linux UDP GSO and Felix's MTU cap

    Raising Felix's QUIC MTU on Linux stalled delivery for good, because UDP GSO turns ten packets into one datagram the kernel refuses and quinn never falls back; this is how we found it, why the cap is 6,550, and why 4,096 is the default.

    What Felix is, how a publish travels from a client to disk to every subscriber, why it is built that way, and how to run it on your laptop in five minutes.
