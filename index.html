One system for your events, state and work.

Felix is an open-source, distributed platform for streams, caches, queues and counters, all on one replicated log. Written in Rust.

Read the docs GitHub
Why Felix

Infrastructure should make software simpler.

Most applications piece together one system for events, another for queues, another for state, and one more to move data between them. In Felix, events, work and state are three ways of operating over the same data.

One system. One durable foundation.
Multiple ways to use your data.

Fast enough for real-time applications, durable enough to trust, and simple enough that you can easily figure out what happened when something fails.

How Felix is different

One log where you'd run four systems

Streams, key-value caches, queues and counters all sit on one replicated log, behind one access model. And a slow subscriber falls behind on its own.

Quickstart

Publish and subscribe

Once felixctl has a context for your cluster, each step is one command. The guide starts a local cluster with a stream named orders and a cache named users.

Try it with felixctl 
# one terminal
felixctl sub orders

# another
felixctl pub orders 'hello'
felixctl cache put users alice 'online'
felixctl cache get users alice
felixctl topology orders
use felix_client::{AckMode, Client, ClientConfig};
use std::net::SocketAddr;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let quinn = quinn::ClientConfig::with_platform_verifier();
    let config = ClientConfig::optimized_defaults(quinn);
    let addr: SocketAddr = "127.0.0.1:5000".parse()?;
    let client = Client::connect(addr, "localhost", config).await?;

    let publisher = client.publisher().await?;
    publisher
        .publish("acme", "prod", "events", b"Hello Felix".to_vec(), AckMode::None)
        .await?;

    let mut subscription = client.subscribe("acme", "prod", "events").await?;
    while let Some(event) = subscription.next_event().await? {
        println!("Received: {:?}", event.payload);
    }
    Ok(())
}
import os
import felix

with felix.Client(
    "127.0.0.1:5000", tenant_id="acme", token=os.environ["FELIX_TOKEN"]
) as client:
    with client.subscribe("acme", "prod", "events") as events:
        client.publish("acme", "prod", "events", b"Hello Felix")
        for event in events:
            print("Received:", event.payload)
import { Client } from "felix-client";

const client = await Client.connect("127.0.0.1:5000", "acme", process.env.FELIX_TOKEN!);
const events = await client.subscribe("acme", "prod", "events");
await client.publish("acme", "prod", "events", Buffer.from("Hello Felix"));

for (;;) {
  const event = await events.nextEvent();
  if (event === null) break;
  console.log("Received:", event.payload.toString());
}

Features, guarantees and numbers

One log, many ways to use it

Streams, caches and queues on one replicated log, with conditional publish, range reads, fine-grained access and Kafka clients.

What Felix does

Shards, replicas and failover

A Quorum write is acknowledged once a majority of the replica set holds it, and only a replica holding every acknowledged record can be promoted.

How replication and failover work

Tested against crashes, partitions and power loss

TLA+ models, a history checker that drives a real cluster through faults, power-loss sweeps of the storage engine, client conformance and fuzzed decoders.

How we test it
Measured on one broker: 4.1 GB/s published in memory, 1.43 GB/s durable, and 345 microseconds at p50 from a durable publish to delivery.

Use cases

What people build with it

Config and feature flags

Every service reads the current value, then every change after it, with no gap.

Live updates at high fanout

One publish reaches every subscriber, and a slow one never holds up the rest.

Leases, locks and idempotency

Compare-and-set writes with expiry times that survive a restart.

Events and state together

Write an event and the state it changes as one record, with no outbox.

Work queues

Jobs retried after a timeout and set aside after too many attempts.

Coming from Kafka

Point existing Kafka producers at Felix and move consumers over one at a time.

felix-canvas

0.3.2

A multiplayer drawing canvas with live cursors, rich text, history you can scrub, and per-room sign-in.

GitHub Docs for felix-canvas Quick start

felix-canvas

curl -fsSL https://github.com/GetFelix/felix-canvas/releases/download/v0.3.2/felix-canvas-compose-0.3.2.tar.gz | tar xz
cd felix-canvas-compose-0.3.2
sed -i.bak \
  -e "s|^FELIX_BOOTSTRAP_TOKEN=.*|FELIX_BOOTSTRAP_TOKEN=$(openssl rand -base64 32)|" \
  -e "s|^FELIX_RAFT_PEER_TOKEN=.*|FELIX_RAFT_PEER_TOKEN=$(openssl rand -base64 32)|" .env
docker compose up -d

Needs Docker or Podman with Compose 2.20 or later; with Podman, run podman compose up -d (see Docker or Podman). Open localhost:8787 in two windows, sign in as ana and ben, and draw. The self-hosting guide covers sign-in, TLS and Kubernetes.

felix-webhook-relay

0.2.0

A webhook relay that stores each webhook durably, delivers it with retries, and replays any endpoint after an outage.

GitHub Docs for felix-webhook-relay Quick start

felix-webhook-relay

curl -fsSL https://github.com/GetFelix/felix-webhook-relay/releases/download/v0.2.0/felix-webhook-relay-compose-0.2.0.tar.gz | tar xz
cd felix-webhook-relay-compose-0.2.0
sed -i.bak \
  -e "s|^FELIX_BOOTSTRAP_TOKEN=.*|FELIX_BOOTSTRAP_TOKEN=$(openssl rand -base64 32)|" \
  -e "s|^FELIX_RAFT_PEER_TOKEN=.*|FELIX_RAFT_PEER_TOKEN=$(openssl rand -base64 32)|" \

Needs Docker or Podman with Compose 2.20 or later; with Podman, run podman compose up -d --wait (see Docker or Podman). Keep .env, since the relay cannot open its stored secrets without RELAY_SECRET_KEY. Open localhost:8090/admin/acme to sign in; the README walks through the first endpoint.

felix-gateway

0.6.0

A WebSocket gateway between browsers and Felix, with sign-in narrowed to one room or match.

GitHub Docs for felix-gateway Quick start

felix-gateway

git clone --depth 1 --branch v0.6.0 https://github.com/GetFelix/felix-gateway
cd felix-gateway
dev/up.sh
export GATEWAY_FELIX_CA_FILE=dev/state/broker-cert.pem GATEWAY_SCOPE_FILE=dev/scope.toml
export GATEWAY_TENANT=demo GATEWAY_OIDC_CLIENT_ID=felix-gateway
cargo run -p felix-gateway

Needs Docker or Podman, Rust 1.97 and Node 24; set CONTAINER_ENGINE=podman to pick Podman (see Docker or Podman). The gateway listens on localhost:8787; connect from a browser app with npm install felix-gateway-client.
