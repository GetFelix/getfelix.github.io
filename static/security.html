Security

How Felix is secured

Felix is pre-1.0 and has not had an external security review. The docs say which protections exist and which do not.

What Felix protects

  • Client connections are encrypted with TLS 1.3 over QUIC. The Kafka and MQTT listeners use TLS too.
  • Brokers and control-plane members authenticate each other with mutual TLS, and each one has its own certificate.
  • Tokens come from your identity provider through OIDC token exchange.
  • Access is tenant-scoped RBAC, enforced at the broker.
  • Credentials expire, and a connection ends when its credentials do.
  • Acknowledged data is kept by quorum replication.

A hardened deployment

The defaults are meant for a laptop. For production:

  • Give brokers a real certificate and refuse to start without one.
  • Require client certificates, and bind each to its token's subject.
  • Use mutual TLS between brokers and between control-plane members, one certificate per node.
  • Serve the control-plane API over HTTPS, and keep bootstrap off except when you use it.
  • Encrypt data on disk at the filesystem or block layer. Felix does not do this for you.

Report a vulnerability

Use a private GitHub Security Advisory. Please do not open a public issue.
